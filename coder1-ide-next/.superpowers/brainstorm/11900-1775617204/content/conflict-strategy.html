What happens when a customer already has their own setup?

Many Claude Code power users have existing CLAUDE.md files, MCP configs, and hooks. How should the Power Pack handle conflicts?

A

Skip if exists (safe, hands-off)

If ~/.claude/CLAUDE.md already exists, don't touch it. Only install what's missing. The customer keeps full control — Coder1 never overwrites anything.

Pros

  • Zero risk of breaking existing setups
  • Customers trust it immediately

Cons

  • Power users get no benefit from Coder1 defaults
  • Harder to ensure consistent experience
B

Append a Coder1 section (non-destructive merge)

Add a clearly marked # Coder1 Configuration block to the bottom of any existing file. MCP servers are added to existing ~/.mcp.json rather than replacing it.

Pros

  • Customer gets Coder1 defaults AND keeps their setup
  • Visible, auditable — customer can see what was added

Cons

  • Could produce duplicate rules
  • File gets messy over time
C

Backup + replace (opinionated takeover)

Back up existing files to ~/.claude/CLAUDE.md.backup, then install the Coder1 template fresh. Customer is shown a diff and can restore the backup anytime.

Pros

  • Consistent experience for all customers
  • Coder1 defaults always apply

Cons

  • Some customers will feel violated
  • Risky if backup/restore has bugs
D

Ask on first connect (interactive setup)

On first bridge pairing, show a one-time setup screen in the IDE: "We found an existing CLAUDE.md — keep yours, merge, or replace with Coder1 defaults?" Customer chooses.

Pros

  • Maximum transparency and customer trust
  • Power users feel respected

Cons

  • Adds friction to first-run experience
  • Decision fatigue for new users
