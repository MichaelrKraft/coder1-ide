How should customers get these pre-configured setups?

The delivery model shapes everything — UX, complexity, and adoption rate

A

Auto-push on bridge connect

When a customer pairs their bridge for the first time, Coder1 automatically installs the full config bundle — MCP servers, hooks, CLAUDE.md — onto their machine. Zero friction, zero decisions.

Pros

  • Instant value, no effort
  • 100% adoption

Cons

  • Could conflict with existing setup
  • No customer choice
B

One-click install from the IDE

A "Claude Code Starter Kit" button in the Coder1 IDE. Customer clicks it, bridge installs the curated bundle onto their machine. Opt-in but frictionless.

Pros

  • Customer is aware of what's installed
  • Easy to re-run or update

Cons

  • Requires customer to find + click it
  • Lower adoption than auto
C

Marketplace / pick-and-choose

A browsable library of tools and configs (context-mode, hooks presets, CLAUDE.md templates). Customers select what they want and install à la carte.

Pros

  • Maximum customer control
  • Differentiating product feature

Cons

  • Most complex to build
  • Decision fatigue for new users
D

Opinionated default + optional extras

Auto-install a curated "Coder1 Power Pack" on bridge connect (safe, non-destructive defaults), then offer an optional marketplace for extras. Best of A + C.

Pros

  • High adoption + power-user flexibility
  • Progressive disclosure

Cons

  • More work to build both layers
