## What is Session Management?

Session Management in Coder1 captures your entire development context - code changes, terminal history, file operations, and AI interactions - into restorable snapshots called **checkpoints**.

<Callout type="success" title="Perfect Handoffs">
**"Continue where I left off"** becomes literally possible. Share checkpoints with teammates or AI agents for instant context loading.
</Callout>

## Core Concepts

### 1. Sessions

A **session** represents a single coding session with:
- Unique identifier (e.g., `session-1756558936429`)
- Start/end timestamp
- Terminal history (complete PTY output)
- File changes (before/after snapshots)
- Editor state (open files, cursor positions)
- AI interactions (prompts and responses)

### 2. Checkpoints

**Checkpoints** are restorable snapshots created:
- **Manually**: Click "Save Checkpoint" button
- **Automatically**: Every 10 minutes when code changes detected
- **On AI Team Completion**: When agents finish their tasks

## Restoring from Checkpoints

### Restoration Process

<Steps>
  <Step title="Open Sessions Panel">
    Click "Sessions" in the left sidebar to view all sessions and checkpoints
  </Step>
  
  <Step title="Select Checkpoint">
    Browse checkpoints with:
    - Timestamp
    - Description
    - File changes count
    - Terminal activity summary
  </Step>
  
  <Step title="Choose Restore Method">
    **Sandbox Mode** (Recommended):
    - Opens checkpoint in separate terminal tab
    - No changes to main workspace
    - Safe for exploration
    
    **Direct Restore**:
    - Restores files to main workspace
    - Overwrites current state
    - Creates backup checkpoint first
  </Step>
  
  <Step title="Review Changes">
    Checkpoint loads with:
    - Terminal history replayed in new tab
    - Files opened in editor tabs
    - Cursor positions restored
    - AI context available
  </Step>
</Steps>

### Sandbox Mode (Recommended)

**Sandbox Mode** is the safe way to explore checkpoints:

```typescript
// What happens in Sandbox Mode:
1. New terminal tab created: "Checkpoint [timestamp]"
2. Terminal history replayed in this tab
3. File changes shown in diff view (not applied)
4. Editor opens files read-only
5. No impact on main workspace

// Benefits:
✅ Risk-free exploration
✅ Compare checkpoint vs current state
✅ Review before restoring
✅ Multiple checkpoints open simultaneously
```

<Callout type="success">
**Pro Tip**: Use Sandbox Mode to review AI Team agent work before merging into main workspace.
</Callout>

## Real-World Workflows

### Workflow 1: Solo Developer Handoff

```bash
# End of your coding session
1. Click "Generate Session Summary"
2. Export as Markdown
3. Commit summary with code:
   git add summary.md src/
   git commit -m "feat: Add authentication system

   See summary.md for complete session details"

# Next session (days/weeks later)
1. Read summary.md
2. Open last checkpoint in Sandbox Mode
3. Review terminal history and file changes
4. Continue with full context restored
```

### Workflow 2: Team Collaboration

```bash
# Developer A finishes feature
1. Create checkpoint: "Auth system complete - ready for review"
2. Generate session summary
3. Share checkpoint ID and summary with team

# Developer B reviews
1. Load checkpoint in Sandbox Mode
2. Review changes without affecting their workspace
3. Test functionality in checkpoint terminal
4. Provide feedback with full context

# Developer C continues work
1. Restore checkpoint to main workspace
2. Has complete history and context
3. Continues development seamlessly
```

### Workflow 3: AI Agent Handoff

```bash
# Human codes for 2 hours
1. Create checkpoint: "Implemented UI components"
2. Generate summary with "Continue building backend API"
3. Export summary as JSON

# Hand off to AI Team
1. Load checkpoint
2. Provide AI agents with summary JSON for context
3. Agents understand current state and continue autonomously

# AI Team completes work
1. Automatic checkpoint created on completion
2. Summary includes AI agent actions
3. Human reviews in Sandbox Mode before merging
```

## Advanced Features

### Checkpoint Filtering

Checkpoints intelligently filter terminal history:

```typescript
// Terminal history filtering (automatic)
Before filtering: 15,000 lines
After filtering: 3,000 lines (80% reduction)

// Filters out:
❌ Duplicate status lines ("Building... 45%", "Building... 46%", ...)
❌ MCP server progress indicators (repeated patterns)
❌ ANSI escape codes and control sequences
❌ Empty lines and whitespace-only lines

// Preserves:
✅ Command inputs
✅ Important output messages
✅ Error messages and warnings
✅ Completed operation confirmations
```

<Callout type="info" title="Performance">
Filtering reduces checkpoint size by ~80% and restoration time by ~75%, making checkpoints lightweight and fast to load.
</Callout>

### Parallel File I/O

Checkpoint creation uses parallel file operations:

```typescript
// Standard (slow): Read files sequentially
Time: 8-12 seconds for 50 files

// Coder1 (fast): Parallel file I/O
Time: 2-3 seconds for 50 files
Improvement: 3-5x faster

// Implementation
const fileOperations = files.map(file => 
  fs.promises.readFile(file, 'utf-8')
);
const contents = await Promise.all(fileOperations);
```

### Git Integration

Checkpoints integrate with git for smart diffing:

```bash
# Checkpoint includes intelligent git diff
git diff --no-color HEAD

# Smart context detection:
- Shows 3 lines of context around changes
- Excludes build artifacts and node_modules
- Highlights actual code changes vs formatting
- Includes commit messages from checkpoint period
```

### Checkpoint Settings


## Troubleshooting

### Checkpoint Creation Slow

**Symptom**: "Saving checkpoint..." takes >15 seconds

**Solutions**:
1. Reduce terminal history limit:
```bash
TERMINAL_HISTORY_MAX_LINES=2000
```
2. Enable compression:
```bash
CHECKPOINT_COMPRESSION=true
```
3. Exclude large files via `.gitignore`

### Checkpoint Restoration Fails

**Symptom**: "Failed to restore checkpoint"

**Solutions**:
1. Use Sandbox Mode instead of Direct Restore
2. Check for file conflicts:
```bash
git status  # Ensure no uncommitted changes
```
3. Verify checkpoint integrity:
```bash
# Check checkpoint file exists and is readable
ls -la .coder1/checkpoints/
```

### Session Summary Empty

**Symptom**: "No significant changes detected"

**Solutions**:
1. Ensure terminal has activity (run at least one command)
2. Make file changes (even small edits count)
3. Check API key is configured:
```bash
echo $ANTHROPIC_API_KEY  # Should output key
```

### Sandbox Terminal Content Bleeding

**Symptom**: Checkpoint content appears in main terminal

**Solutions**:
1. **Fixed in latest version** (October 3, 2025)
2. Ensure using event listener filtering
3. Verify `localStorage` isolation between terminals
4. Restart IDE if issue persists:
```bash
npm run dev
```

## Best Practices

### When to Create Checkpoints

**Good Times**:
- ✅ Before major refactoring
- ✅ After completing a feature
- ✅ Before experimenting with risky changes
- ✅ When switching between tasks
- ✅ End of work session

**Avoid**:
- ❌ During active typing
- ❌ While tests are running
- ❌ When compilation is in progress

### Checkpoint Descriptions

**Good Descriptions**:
- ✅ "Auth system complete - JWT working, tests passing"
- ✅ "Before database migration - stable state"
- ✅ "Experiment with new state management - rollback point"

**Poor Descriptions**:
- ❌ "checkpoint"
- ❌ "stuff"
- ❌ "test"

### Storage Management

```bash
# Regularly clean old checkpoints
npm run clean-checkpoints

# Export important checkpoints before cleanup
# Archive critical session summaries
# Use git tags for major milestones
```
